# B站收藏管理（bilibili-collector）

一个**本地桌面应用**，用来整理、管理你收藏的 B 站视频。做它的初衷很简单：B 站收藏夹越来越乱、想找某条视频翻半天，于是想要一个「自己的、本地的、能搜索能打标签能统计」的收藏管理器。

> 说明：这是一个**个人自用**的收藏整理工具，**不是** B 站第三方客户端，也不复刻 B 站的播放功能。数据全部存在本地，不经过任何服务器。

## 功能一览

### 一、视频收集

- **粘贴链接自动抓取**：粘贴一个 B 站视频链接，自动抓取标题、封面、BV 号、UP 主名字与头像、播放量/弹幕/点赞等数据、视频时长、简介、投稿时间与分区（只抓公开页面的元信息，无需登录、无需 Cookie）
- **登录 B 站 + 一键导入收藏夹**：应用内弹窗扫码登录，登录后列出你的所有收藏夹，选一个即可分页拉取全部视频入库，自动跳过已存在的条目
- **拉取「稍后再看」**：一键把 B 站「稍后再看」列表整个拉下来，存进独立分区
- **搜索 B 站全站**：输入关键词直接搜 B 站全站视频（走官方网页端接口 + wbi 签名），结果是**预览勾选**式的——你自己挑要哪些再入库，存进「搜索导入」分区
- **导入他人分享**：支持**拖拽 `.json` 文件进窗口**或点「导入分享文件」走系统文件对话框，把别人导出的收藏列表导入进来
- **下载视频到本地**：列表每行「⬇ 下载」，选清晰度与保存位置后把视频存成本地 `mp4`（音视频自动合并，见下方「下载视频」章节）
- **自动带上 B 站标签**：导入收藏夹、拉取稍后再看、搜索入库、手动粘贴时，会把视频在 B 站的**原始标签一并抓下来作为默认标签**（单个视频最多 20 个），直接就能拿来筛选；**已经手动打过标签的记录不会被覆盖**
- **标签带来源分类**：抓标签时顺带拿到 B 站自己给的 `tag_type` 与平台**主题分词** `participle` —— 于是能区分「UP 主频道标签」和「B 站活动 / 话题标签」（如 `阴阳师拾此一瞬`），并用平台分词交叉验证哪些标签更可信

### 二、浏览与查找

- **列表展示**：封面缩略图 + 标题 + UP 主头像 + 时长 + 播放量 + BV 号 + 收藏日期
- **关键词搜索**：按标题 / BV 号 / 链接 / 标签模糊匹配
- **标签筛选**：标签自动聚合成可点击胶囊，点一下即筛选
- **追番标记**：标记「看过 / 没看」，配合「全部 / 未看 / 已看」三态筛选，可当追番清单用
- **失效筛选**：检测出的失效视频可一键「只看失效」
- **分享者筛选**：分享导入分区里，可按「是谁分享的」筛选
- **六种排序**：收藏时间（新→旧 / 旧→新）、播放量（高→低）、时长（长→短）、发布时间（新→旧）、UP 主（A→Z）
- **一键跳转**：点标题用网页端打开，顶部按钮直接拉起 B 站桌面客户端（没装客户端会自动退回网页版）

### 三、整理与清理

- **单条编辑**：改标签、改标题、切换看过状态、删除
- **批量打标签**：给「当前看到的那批视频」一次性追加标签（已存在的自动跳过）
- **批量删除**：一键删掉「当前看到的那批视频」（带二次确认）
- **标签管理**：查看每个标签被用了多少次，支持**重命名**、**合并同义标签**（如「学习」+「教程」→「学习」，自动去重）、**删除无用标签**（只摘标签，不动视频）；弹窗顶部可按**来源筛选**（全部 / 活动话题 / UP 标签 / 平台认证 / 可整合），活动话题带橙色 `活动` 标记、被平台分词认可的带绿色 `✓`，点「🧬 同族」可展开**同前缀的一族**（如 `阴阳师拾此一瞬` / `阴阳师执火燎原` / `阴阳师十周年`），点族名一次勾选全族
- **失效视频检测与清理**：一键体检，把被删除 / 转私密 / 仅 UP 主可见的稿件标红，再批量清掉

### 四、数据与统计

- **统计面板**：顶部**大字号**显示当前分区的收藏总数与**收藏总时长**（如「12 小时 45 分」），展开后可看 **Top 12 最多标签** 与 **Top 12 收藏最多的 UP 主**（横向条形占比），以及已看/未看/失效分布
- **导出分享文件**：把当前列表导出为紧凑 `.json`（自带你的账号名，方便别人辨认来源）
- **检查更新**：启动后自动检查一次有没有新版本（带 30 分钟缓存），也可以手动点；**三通道自动降级**，万一网络受限也不影响使用
- **本地存储**：所有数据存在本地 SQLite 文件里，关掉重开不丢，不经过任何服务器

### 五、外观与个性化

- **自定义壁纸**：应用背景不再是单调纯色 —— 可以换**预设壁纸**（项目 `resources/wallpapers/` 下的图片会随安装包一起分发；往目录里丢图后打开面板即出现，**无需改代码、无需重启**），也可以**自选本地图片**（挑了之后会复制一份到应用数据目录，所以原图移动、删除、换机器都不影响）；不想用壁纸时一键「不用壁纸」
- **卡片半透明 + 背景模糊**：全站面板统一可调透明度（30% ~ 100%），「壁纸好看」与「文字看得清」之间自己找平衡；还可以给壁纸加 0 ~ 24px 模糊
- **观感优先，但不牺牲可读性**：壁纸只铺在最底层，上面压一层固定遮罩；弹窗的透明度有独立下限，拉到最透也不会被背后的文字干扰
- **设置只存在本地**：外观偏好写在本地配置文件里，**不写进数据库，也不会混进「导出列表」的分享文件**（别人导入你的列表不会带上你的壁纸）

## 四个数据分区

顶部标签页把数据分成**四个互相隔离的分区**，每个分区都是**独立的数据表**，互不干扰：

| 分区 | 数据来源 | 说明 |
|------|----------|------|
| **我的收藏** | 手动粘贴链接 / 导入收藏夹 | 主分区 |
| **稍后再看** | 一键拉取 B 站「稍后再看」 | 上限 100 条（B 站自身的限制） |
| **分享导入** | 别人导出的 `.json` 文件 | 按「分享者」区分来源 |
| **搜索导入** | 应用内搜索 B 站全站后勾选入库 | 按 `bvid` 去重，不会重复存 |

之所以用**四张独立表**而不是「一张表加个标记」，是因为 BV 号在单表里是唯一约束——同一个视频如果既在你收藏里、又在稍后再看里、还被朋友分享给你、你又自己搜到过，单表会打架。分表后**同一个视频可以在四个分区各存一份**，互不影响，也免去了重建表的迁移风险。

**分享导入的去重规则**：同一个人 + 同一个视频只保留一条；不同人分享同一个视频则各存一条。所以重复导入不会让数据膨胀。

> 四个分区里的**收藏、搜索、标签筛选、看/未看筛选、批量打标签、批量删除、失效检测、排序、统计**功能**完全一致**——因为这些能力都跟着「当前分区」走。

## 数据存储

- **位置**：`%APPDATA%\bilibili-collector\bilibili-collector.db`（Electron 的 `userData` 目录）
- **模式**：SQLite **WAL**（读写更稳定，适合频繁小事务）
- **表**：`videos`（收藏）、`toview`（稍后再看）、`shared`（分享导入）、`search`（搜索导入）
- **主要字段**：`bvid` / `url` / `title` / `cover` / `author` / `author_face` / `duration` / `description` / `pubdate` / `tname` / `stat`(JSON) / `tags`(JSON) / `watched` / `fav_time`(收录时间戳) / `cid`(用于下载取流) / `invalid`(失效标记) / `created_at`
- **标签来源**：`tags`（JSON 数组）里既可能是你手动打的标签，也可能是导入时从 B 站一并带下来的原始标签；`tag_meta`（JSON 对象）记录每个标签的来源 —— `up`（UP 主频道标签）/ `topic`（B 站活动话题）/ `desc`（从简介 `#话题#` 里提取的），旧数据没有这一列，界面会显示成「未分类」；`participle`（JSON 数组）存 B 站平台算出的主题分词，用来给标签打「可信」标记
- **不覆盖原则**：重新导入时只补「标签为空 / 没有来源记录」的字段，**不会覆盖**你整理过的标签与来源信息
- **`shared` 额外字段**：`share_from`（分享者昵称）、`share_mid`，唯一约束为 `UNIQUE(bvid, share_from)`
- **自动迁移**：程序启动时用 `PRAGMA table_info` 检查缺哪列就补哪列，老版本数据库可以直接升级，不会丢数据
- **外观设置**：`%APPDATA%\bilibili-collector\settings.json`（壁纸选择、卡片透明度、背景模糊）；自选的壁纸图片会保存在 `%APPDATA%\bilibili-collector\wallpapers\`。这两项都属于「界面偏好」，**不进数据库、也不参与「导出列表」**，和你的收藏数据完全隔离

> 想备份就直接复制这个 `.db` 文件；也可以用「导出列表」导出一份 `.json` 作为可读备份。

## 下载视频

在列表里点任意视频右侧的「**⬇ 下载**」，选清晰度与保存位置，即可把它的音视频合并成 `.mp4` 存到本地，文件名格式为 `标题-BV号.mp4`（标题里的非法字符会自动替换）。

**清晰度与登录态**：程序先请求一次取流接口，把**你这个账号实际能拿到的档位**列出来（默认选中 1080P，拿不到的自动往下退并标注）。**1080P 及以上通常需要登录 B 站账号**；未登录只能拿到 360P / 480P 这类低清晰度。

**为什么要内置 ffmpeg**：B 站 DASH 流是**音视频分开**的（视频流 + 音频流），必须合并才能得到可播放的 `mp4`。安装包已自带精简版 `ffmpeg.exe`（gyan.dev essentials build，约 79 MB），**开箱即用、无需另装**。程序查找顺序为「安装包内置资源 → 项目 `resources/ffmpeg` → 系统 PATH」，所以直接跑源码时用系统已装的 ffmpeg 也可以。合并采用 `-c copy` **流拷贝**——不重新编码，无损且秒级完成。

下载过程会显示「视频 / 音频 / 合并」三个阶段与百分比，**可随时取消**；主下载地址失败会自动切换备份地址。

**不支持的场景**（会给出明确提示，不做绕权处理）：

| 场景 | 说明 |
|------|------|
| 充电专属视频 | 走的是同一个取流接口，但**鉴权在服务端**——账号必须有对应充电记录才能拿到流 |
| PGC 番剧 / 付费课程 | 接口不同，**不支持** |

> 下载功能的定位是**个人自用备份**（把收藏 / 稍后再看的视频存到本地离线看）。请**不要**用于二次分发或商用，也不要指望它绕过任何付费权限。

## 开发指南

### 架构

典型的 Electron 三进程结构：

- **主进程**（`src/main/index.js`）：所有业务逻辑——抓取、SQLite 读写、B 站登录与接口调用、导入导出、文件对话框、失效检测，全部通过 `ipcMain.handle` 暴露成 IPC 通道
- **预加载层**（`src/preload/index.js`）：用 `contextBridge` 把 IPC 能力以 `window.api.xxx` 的形式安全地暴露给前端（渲染进程 `sandbox: false`，无 Node 权限）
- **渲染进程**（`src/renderer/`）：React 界面，只调用 `window.api.*`，不直接碰数据库

**数据分区靠白名单映射**：`SOURCE_TABLES = { fav: 'videos', toview: 'toview', shared: 'shared', search: 'search' }` + `tableFor(source)`，所有 SQL 表名都从白名单取，避免拼接注入。

### 调试技巧

- 抓取相关的 `fetch-video-info`、导入、检测等都在主进程，改完看终端输出。
- 想直接跑主进程逻辑做验证，可以借 Electron 自带的 Node（因为 `better-sqlite3` 是按 Electron ABI 编译的，系统 node 跑不了）：

  ```bash
  ELECTRON_RUN_AS_NODE=1 ./node_modules/electron/dist/electron.exe your-script.cjs
  ```

  在脚本里可以给 `require('electron')` 打桩（`app.getPath` 指向临时目录、`whenReady` 直接 resolve、`ipcMain.handle` 把 handler 收进 Map），再 `require('./out/main/index.js')`，就能加载**打包后的真实主进程**并直接调用它注册的 IPC，等于跑了一遍真实业务代码。

## 注意事项（请务必阅读）

### 1. 抓取合规边界

- **单条手动抓取**：只请求「公开视频页面」，只提取 `<meta>` 标签里 `og:` 元信息，以及页面自带的 `__INITIAL_STATE__` 公开数据。这些是任何未登录用户打开网页都能看到的内容，不涉及你的账号与隐私。
- **登录导入走官方接口**：登录后的一键导入，走的是 B 站网页端自用的收藏夹接口（`/x/v3/fav/resource/list`），本质是「用你自己的 Cookie 拉你自己的收藏夹」，属于合理自用，风险远低于批量爬公开页面。

### 2. 登录与 Cookie 安全

- 登录产生的 `SESSDATA` 等 Cookie 是**你账号的登录凭证**，请勿把登录态截图发给他人。
- 登录凭证在本地**已加密保存，不会以明文形式留在磁盘上**；应用不写进代码、不上传任何服务器，且重启后无需重新扫码即可恢复登录态。
- 加密解决的是「文件被拷走 / 换机器 / 备份同步」这类场景；**已经运行在你电脑上的恶意程序不在防护范围内**。所以仍建议：**不要轻易把 Cookie 复制粘贴给第三方**。

### 3. 频率控制与风控

- 导入收藏夹时，程序在翻页之间**内置了 1.5 秒延时**；失效检测是**4 并发 + 每条 150ms 间隔**；导入时抓取 B 站标签是**3 并发 + 每条 250ms 间隔**。这些都是用于控制请求频率、避免触发 B 站风控的。**请勿自行调短或移除这些延时**，否则可能触发 `412` 封 IP、弹验证码，甚至导致登录态失效。
- 失效检测会逐条请求 B 站，条数多时耗时较长（100 条约十几秒），请耐心等待。
- 抓取标签同样只能逐条请求（B 站没有批量查标签的接口），100 条约多花 8~10 秒，界面上会显示进度；只给「标签信息不全」的记录抓（新记录，或已导入但缺标签来源的旧记录），抓全的不再重复请求。

### 4. 失效判定是「保守策略」

- 只有 B 站明确返回「稿件不存在 / 不可见 / 仅 UP 主可见 / 权限不足」时，才会被标记为失效。
- 其它情况（例如稿件审核中）或网络异常，一律记为「无法确认」并**保持原标记不变**——宁可不标，也绝不误删你的正常收藏。
- 视频若恢复上架，重新检测会自动「洗白」。

### 5. 接口非官方，可能失效

- 收藏夹、稍后再看、视频详情等接口都是 B 站网页端**内部接口**（非官方开放 API、无正式文档）。如果 B 站改版或加了签名校验，相关功能可能失效，届时需更新适配。

### 6. 封面 / 头像防盗链

- B 站图片域名（`*.hdslb.com`）有防盗链，程序已内置 `Referer` 修复。如果你手动改动了主进程里 `session.webRequest` 相关代码，可能导致封面/头像裂图。

### 7. 分享文件的信任边界

- 导入别人的分享文件时，程序**只读取视频元信息**（标题、封面、作者、时长、标签等）并写入本地数据库，不执行任何来自文件的内容。
- 但仍建议只导入你信任的人给的 `.json` 文件。

### 8. 「检查更新」为什么会报 403 / 限流

如果点「检查更新」提示 **HTTP 403**，通常是这个原因，**不是软件坏了**：

- 检查更新走的是 GitHub 的**匿名**接口（`/releases/latest`），官方限额是**每个出口 IP 每小时 60 次**。
- 如果你开着代理（Clash / V2Ray 之类），请求是从**代理的出口 IP** 发出去的，而那个 IP 往往是**多人共享**的——额度可能早被别的用户用光，于是 GitHub 回 `403 API rate limit exceeded`。
- 程序对此已做处理：**API 失败会自动降级到备用通道**（仓库 `package.json` → jsDelivr CDN）重新核对版本；自动检查还带 **30 分钟缓存**，不会每次启动都去请求。
- 万一所有通道都失败，界面会给一个**「前往下载页」**按钮，直接手动去 Release 页面看最新版本即可，不影响任何其它功能。

### 9. 下载功能的使用边界

- 下载依赖 B 站网页端的**取流接口**，能拿到的清晰度上限**取决于你的账号**：未登录只有低清，1080P 及以上一般需要登录，部分高码率档位还需要大会员。
- 程序**不做任何绕过付费 / 权限的处理**——充电专属、PGC 番剧、付费课程均不支持，请勿期望用它解锁受限内容。
- 下载 CDN 流必须携带 `Referer`（程序已内置），否则会被回 403。
- 请把下载内容用于**个人自用备份**，不要二次分发或商用。

  - 不想用壁纸时点「不用壁纸」即可恢复原本的纯色背景，「恢复默认」一键回到初始外观

- **壁纸实现上不将就**：壁纸走自定义协议按需流式加载（不转 base64、不额外吃内存，大图也不卡）；壁纸层固定在内容之下并加了一层遮罩，保证任何图片上文字都清晰；首屏在 React 渲染前就同步铺好壁纸，**不会出现先黑底再跳壁纸**的闪屏
- **不污染你的数据**：外观偏好存在本地配置文件里，**不写进数据库，也不会混进「导出列表」的分享文件**（别人导入你的列表不会带上你的壁纸）
- **登录凭证加密保护**：登录态改为**加密保存**，磁盘上不再保留明文 Cookie；旧版本的明文凭证会在首次启动时自动完成**无感迁移**（不用重新扫码）。换机器 / 重装系统后需要重新登录一次，收藏数据完全不受影响
- **启动更稳**：初始化流程改为逐项兜底，任何一项初始化失败都**不会再导致窗口打不开**，最多退化成默认外观 / 未登录

- **批量管理**：支持对「当前搜索结果 / 筛选结果」批量打标签、批量删除（筛选结果为空时按钮自动禁用，删除前二次确认）
- **稍后再看独立分区**：一键拉取 B 站「稍后再看」列表，与收藏区完全相同的布局与功能
- **失效视频检测与清理**：逐条探测稿件状态，失效的标红并挂徽章，可「只看失效」后批量清理；判定采取保守策略，不确定的一律不改标记
- **分享导出 / 导入**：导出为紧凑 JSON（无缩进 + 简介截断 200 字，约 961 字节/条，自带导出者账号名）；导入支持拖拽 `.json` 进窗口或走系统文件对话框，进入独立的「分享导入」分区，按分享者区分来源并去重
- **标签管理**：标签使用次数统计、重命名、合并同义标签（自动去重）、删除无用标签
- **统计面板与多种排序**：顶部大字号显示收藏总数与收藏总时长，可展开查看 Top 标签与 Top 收藏 UP 主；新增 6 种排序方式
- **提供安装包**：发布 Windows x64 的 NSIS 安装包（约 84 MB），可直接下载安装，无需配置任何环境
